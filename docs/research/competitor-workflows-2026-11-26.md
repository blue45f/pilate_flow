# 강사의 수업 작성·진행과 회원 예약 흐름 비교

2026-11-26 KST에 한국어·영어로 필라테스 강사용 시퀀스 앱, 수업 플래너, 국내 스튜디오 예약·대기 프로그램을 검색하고 공식 홈페이지, 도움말, 개발자가 등록한 앱스토어 설명을 확인했다. 저장소의 기존 벤치마크에 이름이 나온 제품·교육 체계도 다시 조회했다. 강사가 직접 쓰는 수업 도구 13개, 예약 서비스 9개, 관련 콘텐츠·교육 서비스 8개가 아래 표의 범위다. 시장 전체의 제품 수나 누락 여부는 추산하지 않았다.

강사가 **지난 수업을 고쳐 다시 쓰고, 진행 중에 현재 큐와 다음 준비를 읽는 과정**, 회원이 **예약·대기·취소 후 자신의 횟수를 확인하는 과정**을 비교했다. Forme와 스튜디오플랜의 공개 시연은 Firecrawl 브라우저에서 직접 조작했다. 다른 행은 공개 페이지 탐색 또는 제공자의 기능 설명을 근거로 한다. 로그인된 앱의 동작, 동기화 속도, 정확도, 만족도와 동작 선택의 안전성은 측정 범위 밖이다.

비교표의 30개 제품과 보조 제품 3개에 대해 `rea-agents@6.10.1`의 실제 MCP 세션으로 공개 페이지 스냅숏 34건을 검사했다. 공식 URL, HTML 해시, 증거 ID와 관찰한 화면 요소를 함께 기록했다. 접근성 트리를 읽은 결과와 공개 데모를 직접 조작한 결과는 원장에서 각각 확인할 수 있다. [REA MCP 관찰 원장](./rea-workflows-2026-11-26.json)

## 기존 조사에서 달라진 점

[11월 8일 기록](../rea-peer-service-analysis-20261108/README.md)은 Pilates Anytime과 Merrithew에 대한 당시 REA 관찰을 보관한다. [11월 13일 작성 화면 비교](../sequence-studio-and-motion-quality-2026-11-13.md)와 [11월 16일 조사](./competitor-usability-2026-11-16.md)는 검색·선택·추가·진행과 영상 읽기에 집중했다. 이번에는 국내 강사의 다음 회차 준비, 저장 수업 복구, 회원의 대기·취소와 잔여 횟수 확인까지 비교했다.

[기존 벤치마크](../BENCHMARK_HIERARCHY_1000_ARCHITECTURE.md)가 인용한 Pilavio의 동작 수와 현재 공개 소개의 숫자가 다르다. 이번 판단은 동작 수나 예상 절약 시간에 가중치를 부여하지 않았다. 과거 Balanced Body의 호스트 조회가 실패한 기록과 별개로 현재 공개 홈페이지의 탐색 링크를 확인했다.

### 로컬 브라우저에서 확인한 흐름

- Chromium에서 화면을 320·390·768px 너비로 바꿔 작성 화면과 라이브러리 양쪽에서 `ㄱㅂㅅㄱ`를 입력했다. 작성 화면에서 골반 시계 한 개를 추가했고, 라이브러리에서는 같은 동작 한 개가 담긴 상태로 검색됐다. 초성을 모든 수업 메모에 대입한 첫 구현은 같은 입력으로 169개를 반환했다. 이름·부위·기구 같은 짧은 항목에서 초성을 비교하도록 바꾼 후 같은 조건으로 재확인했다. 일반 단어는 기존처럼 설명·큐에서도 검색한다.
- 같은 세 화면 너비에서 강사 도구를 열고 ‘스마트 추천 코치’로 들어갔다. Tab으로 자식 화면을 조작한 뒤 Escape를 누르면 코치 버튼으로, 다시 Escape를 누르면 작성 도구 더보기로 포커스가 돌아왔다. 320·390px에서는 동작 추가 후 시퀀스와 검색 창을 오가도 입력한 초성이 남았다.
- 진행 모드에서는 두 동작 중 첫 동작을 건너뛰고 두 번째만 완료했다. 기록 창에 실제 진행 시간 3분을 입력해 저장한 뒤, 이력에서 완료한 동작 1개와 180초가 남은 것을 확인했다. 이 결과는 로컬 Chromium에서 측정했다.

- 390×844 모바일에서 빈 수업의 ‘내 시퀀스’ 제목은 화면 위에서 692px 지점에 있어 고정 실행 바에 가려졌다. 수업 조건을 요약하고 동작을 담을 때 실행 바를 표시하도록 변경한 뒤 같은 제목이 411px 지점에 나타났다. 320px 화면에서도 동작 추가 후 실행 버튼 네 개가 모두 화면 안에 들어왔고 각 버튼의 높이는 44px였다. [390px 변경 전](../qa/2026-11-26/mobile-planner-before.webp) · [변경 후](../qa/2026-11-26/mobile-planner-after.webp)
- 390px와 1366px에서 저장한 수업을 삭제하고 새로고침한 뒤 휴지통에서 복구했다. 저장 오류 시 복구 재시도와 같은 ID의 새 수업이 이미 존재하는 경우도 컴포넌트 회귀 검사에 포함했다.
- 데스크톱에서 32단계 수업 링크를 복사해 별도의 390px 브라우저로 가져왔다. 단계 수와 순서, 설명·전환 시간 및 메모 제외 설정이 유지됐다. 인쇄용 A4 PDF의 QR도 독립 판독기로 읽어 URL이 원문과 일치하는지 확인했다.
- 390×844에서 같은 회원 포털을 두 탭으로 열어 예약, 자리 변경, 취소를 진행했다. 좌석을 R5에서 R4로 옮겨도 추가 차감이 없었고 취소 후 남은 수강권은 처음과 같은 7회였다. 9시 59분에 연 확인창에서 10시 시작 시각이 지난 뒤 확정이 차단되는 것도 확인했다.

- 작성 화면에서 30초만 남고 그 안에 들어갈 동작이 없으면 시간 채우기를 표시하지 않았다. 5분 29초가 남았을 때는 4분과 1분 29초 동작을 제안했고, 적용 후 합계가 목표와 일치했다.
- 수업 10개 동작과 수정한 제목을 둔 상태에서 다음 회차 열기를 취소했다. 다시 열어 새 회차를 준비한 뒤 되돌리자 이전 제목과 10개 동작이 복원됐다.
- 두 Chromium 탭에서 QR 미리보기를 연 동안 다른 탭에 수업 사본을 저장했다. 공유 수업 가져오기가 중단된 상태에서 링크와 미리보기가 유지됐고 최신 저장본으로 다시 열어 완료하자 두 수업이 모두 남았다. 일반 자동 저장도 두 탭으로 확인했다. 한 탭에서 제목을 입력하고 화면을 이동한 뒤 최신본을 다시 열고 실행 취소해도, 다른 탭의 저장본과 첫 탭의 초안을 각각 보존했다. 회원이 자리 확인창을 연 동안 강사가 다른 탭에서 폐강한 경우도 재현했다. 이때 예약은 기록되지 않았고 수강권 차감은 0회였다.

## 도해 검증

기존 빌드는 일부 자세의 좌표가 런타임에서 부동소수점 마지막 자리만 달라져도 캐시 검증이 실패했다. Blender가 실제로 읽는 소수점 여섯 자리의 기하 데이터를 기준으로 세 자세와 공통 카메라 구도를 대조하도록 수정했다. 이 과정에서 좌표가 실질적으로 달랐던 네 변주의 정본을 갱신했다. 리포머 세 프레임을 다시 렌더했고 캐딜락 아홉 프레임은 검증한 동일 장면의 이미지를 사용했다. 620개 동작의 1,860프레임을 Node 22·24·26에서 검증했다. 이 검사는 기하와 렌더 캐시의 정합성을 확인한다.

실제 회원 계정 간의 예약 동기화, 실단말에서 화면이 계속 켜지는지, 종이 인쇄물을 휴대폰 카메라로 읽을 수 있는지, 강사들의 작업 시간과 만족도는 이 검증에서 측정하지 않았다.
