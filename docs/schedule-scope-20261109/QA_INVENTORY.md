# Schedule change scope QA
Source: user reattached schedule-saved-history-concept(1).png. Scope: repeat occurrence vs series change selection, not saved/history screens.

- Opening repeated class selects one occurrence and displays exact current date/time/title. No write before saving.
- Desktop/wide tablet panel beside schedule; narrow widths stacked, readable with keyboard/touch and 200% text. Inspect 320, 390, 768, 1024, 1440 and short height.
- Native radios switch with keyboard; Next routes to correct existing form. Cancel, X and Escape close with stable focus return. Next double-click cannot double-open or save.
- Once edit changes only exception; series edit preserves existing per-occurrence cancellation/move. Saving and reload preserve correct visible result.
- Stale or deleted target blocks Next; live store rechecked during deferred form opening. Switching target resets choice. Moved occurrence preserves original identity.
- Nonrecurring class retains existing direct controls. Unrelated schedule, planning and safety features retained.
- Explore navigation away/date changes while panel open, short viewport, week mode with expanded panel, reopen after cancel, external data changes.
- No production deployment or Gemini interaction. Confirm remote main ancestry/trigger configuration before integration.
