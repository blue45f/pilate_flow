# 반복 일정 변경 범위 · 2026-11-09

## 시안과 실제 반영 범위

사용자가 다시 첨부한 `schedule-saved-history-concept(1).png`를 Mac에 공식 준비한 뒤 직접 픽셀로 대조했다. 1,615,304 bytes, 1752×897, SHA-256 `e505cc9b949e298bcaba481d659f4d8593fad09aa419fd12b919aeeaea5c1468`.

이 판의 왼쪽은 태블릿 일정 화면, 오른쪽 두 화면은 모바일 저장 시퀀스와 수업 기록이다. 이번 변경은 일정 화면에서 빠져 있던 **회차 변경 범위 패널**에 한정한다. 별도 저장·기록 화면이나 운동 콘텐츠를 수정하지 않았다.

- 반복 수업 카드의 ‘회차 변경’에서 ‘이번 회차만 / 반복 일정 전체’를 먼저 선택한다.
- 넓은 화면은 목록 오른쪽 패널, 좁은 화면은 목록 위의 단일 열이다. 짧은 높이에서는 패널 내부 스크롤을 허용한다.
- 실제 선택한 수업 제목·날짜·시각을 표시한다. 기본값은 이번 회차만이며, 다른 회차를 선택하면 기본값으로 돌아간다.
- ‘다음’은 기존 개별 변경 또는 반복 일정 편집 폼을 연다. 저장 전에는 일정 데이터가 바뀌지 않는다.
- 개별 이동·취소는 반복 원본 편집 뒤에도 보존된다. 시안의 ‘모든 회차를 함께 변경’이라는 단순 문구 대신, 실제 동작을 정확히 설명한다.
- 패널을 연 뒤 해당 일정이 바뀌면 다음을 막는다. 폼을 열기 직전에도 최신 데이터를 다시 확인한다.
- 취소·X·Escape는 초점을 시작한 카드로 돌려준다. 날짜 탐색으로 카드가 사라졌다면 현재 날짜 제목으로 돌려준다.
- 단발 일정은 기존 직접 편집 동선을 유지한다. 기존 취소·복원·휴무·날짜별 계획 기능과 저장 모델은 유지했다.

## 검증

- 새 범위 선택 테스트 9개 통과: 기본 선택, 정확한 날짜, 취소·Escape·초점, 단일 회차 저장, 반복 편집 시 개별 예외 보존, 두 단계 동시 변경 방어, 이동 회차의 원래 ID 유지, 대상 변경 시 선택 초기화, 날짜 탐색 후 초점 복귀, 단발 일정 경로.
- 일정 관련 기존 45개 테스트 및 새 테스트, 일정 통합 3개 테스트를 별도로 실행했다. 통합 테스트는 범위 선택 → 다음 → 저장 동선으로 갱신했다.
- 실제 Chrome 7조건: 320×760, 390×844, 768×1024, 1024×768, 1440×900, 1024×500, 320×760에서 텍스트 200%.
- 모든 조건에서 문서 가로 넘침 0, 페이지 오류 0. 라디오 화살표, 취소·X·Escape, 모달 초점 복귀, 개별/반복 저장, 기존 예외 보존, 주간 보기, 외부 상태 변경 시 차단, 새로고침 후 저장 지속을 확인했다.
- 화면 캡처를 별도로 확인했고, 200% 텍스트에서 열자마자 하단으로 이동하던 문제를 수정했다. 패널 제목과 선택 대상을 먼저 노출한다. 큰 텍스트와 낮은 높이에서는 세로 스크롤이 필요하다.
- 전체 TypeScript와 변경 파일 ESLint 통과. 전체 ESLint는 기존 MotionAuthoringBatchFigure의 Fast Refresh 경고 1건, 오류 0건.
- 독립 작업 사본의 production build와 PWA 검사: 정적 파일 47개, manifest, PNG 아이콘 통과. 빌드 크기 경고는 기존 대용량 카탈로그 chunk에 남아 있다.
- 별도 읽기 전용 코드 검토에서 범위 내 중대한 회귀·데이터 손실·초점 문제를 찾지 못했다.

## 전체 회귀 검사와 제한

전체 회귀 검사에서는 기존 `dynamicWorkflowFullCompletion.test.tsx`의 회전 상세 도해 기대값 1건이 실패했다. 수정 전 main `53b47d5c9088abdc62927db91c4cd1df59860b91`에서도 동일하게 재현했다. 일정 변경으로 운동 도해 연결이나 안전 설명을 완화하지 않았다. 전체 집계는 최종 실행 결과와 함께 아래에 기록한다.

검증 데이터는 격리된 브라우저의 합성 수업이다. 실제 회원 데이터, iOS Safari/실물 기기, 운영 배포 버전을 검증한 결과가 아니다. 이 변경을 9개 시안 전체의 동일 구현 완료로 확대하지 않는다.

## 배포와 통합 경계

확인한 원격 기준 main은 `53b47d5c9088abdc62927db91c4cd1df59860b91`이다. GitHub 등록 webhook은 없고, main push의 저장소 워크플로는 secret check다. GitHub Pages는 별도 `gh-pages` 브랜치 원본이다. Firebase Hosting은 수동 deploy 명령이며 이번 작업에서 실행하지 않았다. 별도 외부 계정의 모든 자동화 부재까지 보증하는 것은 아니다.

원본 작업 사본과 다른 활성 세션을 수정하거나 중단하지 않았다. 독립 작업 사본에서 변경·검증했으며 운영 배포는 하지 않는다.
