## 확인된 문제와 구현

### 원하는 위치에 동작 추가

`appendExerciseToSequence`는 마지막 위치만 지원했고, 동작 선택기의 성공 판정도 마지막 항목을 가정했다. 중간에 추가하려면 추가 후 다시 이동해야 했다.

- `insertExerciseIntoSequence`는 맨 앞·맨 뒤·특정 항목 뒤를 지원한다.
- 위치는 배열 인덱스 대신 `stepId`로 기억한다. 기준 항목이 사라지면 위치를 다시 고르게 한다.
- 선택 위치는 현재 수업 ID에 연결한다. 다른 수업을 열면 맨 뒤에서 시작하고, 같은 수업에서 기준 항목을 삭제했을 때는 위치 재선택 안내를 유지한다.
- 기존 중복·기구·소도구·난이도 검증을 유지한다. 실패한 위치 삽입은 저장소를 변경하지 않는다.
- 잠금은 기존 `reorderStep`과 같이 항목의 실제 위치를 보호한다. 잠긴 항목을 뒤로 밀게 되는 삽입은 허용하지 않는다.
- 한 번의 저장소 갱신과 한 번의 undo로 삽입한다. 연속 추가는 방금 추가한 항목 뒤로 이어진다.
- 직접 만든 동작은 작성 메모·시간·반복·좌우·초안 스냅샷을 함께 보존한다.

이 위치 선택 방식과 잠금 정책은 경쟁 앱에서 그대로 가져온 규칙이 아니라, 기존 Pilates Flow의 상태·편집 규칙에 맞춘 설계다.

### 저장 수업을 확인한 뒤 사본으로 열기

기존 `사본 열기`는 초안 교체를 확인하기 전에 사본을 저장했다. 취소해도 사본이 남았고, 최근 수업 필터나 그룹명 검색에서는 새 사본과 그 안의 확인 UI가 숨겨질 수 있었다.

- 카드에서 읽기 전용 미리보기를 바로 열 수 있다. 기존 `ClassCueSheetPreview`를 재사용한다.
- 사본 생성 확인은 원본 수업에 연결된 대화상자에서 진행한다. 현재 필터가 확인 UI를 제거하지 않는다.
- `openSavedSequenceCopy`는 미리보기 당시 상태를 확인한 뒤 사본 생성과 작업대 열기를 한 번에 처리한다.
- 취소·닫기·Escape는 사본이나 현재 초안을 변경하지 않는다.
- 원본·기록·현재 그룹을 유지한다. 저장한 사본과 작업 중인 사본은 별도 복사본이며, undo는 이전 작업대 상태를 복원한다.
- 미리보기 이후 수업이나 저장소가 바뀌면 최신 내용을 다시 확인해야 한다.

### 즐겨찾기 분류를 직접 지정

분류 필터에는 여러 분류가 있었지만 카드 하트는 일반 보관과 시그니처만 전환했다. 상세 패널에 기존 `FAVORITE_TAG_META`와 `setExerciseFavoriteTag`를 사용하는 라벨 있는 선택기를 추가했다. 별도의 스키마·필터·수집함은 만들지 않는다. 분류 변경은 수업 순서·검토 기록·수업 이력에 영향을 주지 않는다.

### 수업 진행 중 필요한 정보 우선 표시

기존 진행 화면에는 타이머·좌우 안내·다음 기구 설정·음성·전체 화면 등 기능이 이미 있었다. 현재 큐와 재생 제어보다 앞에 표시되던 3D·호흡 참고 자료와 부가 설정의 노출량을 조절한다.

- `집중 진행`은 현재 동작·타이머·좌우·핵심 큐·현재와 다음 준비·진행 제어를 우선 보여 준다.
- `자료 함께 보기`로 기존 참고 자료를 펼친다. 개별 자료 영역도 직접 열 수 있다.
- 보기 전환은 수업 세션을 다시 만들거나 경과 시간을 초기화하지 않는다.

### 일정·기록에서 실제 자료와 예시를 구분

강사 일정에는 실제 출석 데이터가 없는데도 회원 예약 체험의 계산된 정원이 표시되고 있었다. 이 표시는 제거하고 실제 일정·구성 준비 상태를 유지한다. 기록 화면은 예시 이력을 분석에서 제외한다고 안내하면서도 실제 기록이 없으면 예시를 추천 생성에 사용하던 경로를 고친다. 예시 열람과 명시적 복사는 유지한다.

일정과 기록을 보다가 작업대로 이동한 후 돌아와도 선택 날짜·보기·필터·검색 위치를 이어갈 수 있도록 가벼운 탐색 상태를 보존한다. 수업이나 기록 데이터에 저장하지 않고 현재 탭의 계정 작업 공간별로 구분한다. 잘못된 값이나 저장소 접근 제한이 있으면 기본 화면으로 돌아간다.

### 회원 예약의 빈 결과에서 다음 수업 발견

기존 `다음 수업일 보기`는 같은 주의 날짜만 찾고, 없으면 수업 유무를 확인하지 않은 다음 날로 이동하면서 필터를 초기화했다.

- 빈 결과에서만 이후 4주를 탐색하고 선택한 기구·포커스·예약 가능 필터를 유지한다.
- 취소·휴무·이동 전 날짜를 건너뛰고 조건에 맞는 실제 표시 가능한 회차로 이동한다.
- 탐색 범위 안에 없으면 범위를 명시하고 다른 주 탐색과 필터 초기화를 제공한다. 수업이 없는 날짜를 추천하지 않는다.
- 이동은 읽기 전용이다. 예약·수강권·강사 일정은 변경하지 않는다.
- 실제 예약 서버와 연결되지 않은 현재 회원 기능의 범위를 상단에 `예약 체험`으로 표시한다. 수강권과 잔여 좌석은 예시이고 예약·취소는 이 기기에만 기록됨을 설명한다.

이 날짜 탐색과 예시 표시 개선은 현재 앱의 재현 가능한 문제에서 도출한 설계다. 경쟁 서비스의 예약 엔진이나 서버 동기화를 구현했다는 뜻은 아니다.

### 복원할 백업을 식별하고 계정 연결의 범위 설명

파일 선택 입력이 초기화된 뒤에도 파일명·형식·크기·검증된 v3 생성 시각을 확인할 수 있다. 시간 정보가 없는 이전 형식은 그 사실을 표시한다. 파일명·내용·검사 결과를 한 후보 객체로 관리하고 기존 비동기 요청 확인을 유지하여, 늦게 끝난 읽기가 새 파일의 정보와 섞이지 않게 한다. 취소와 복원 완료 시 후보를 비운다. 기존 충돌 검토·저장소 확인·되돌리기는 유지한다.

설정의 `클라우드 동기화` 단계명도 실제 기능에 맞게 `계정 연결`로 고친다. 기존 계정별 브라우저 작업 공간 동작을 유지하며 서버 동기화를 새로 제공하지 않는다.

## 병합과 배포 분리

사용자의 요청 범위는 코드 구현과 `main` 병합까지다. 기존 main 자동 배포를 그대로 두면 요청 범위를 넘기 때문에 다음과 같이 변경했다.

- `push(main)`: 품질 검사와 빌드 산출물 생성만 실행.
- `pull_request(main)`: 같은 검사를 병합 전에 실행.
- 수동 실행 기본값: 검사와 빌드만 실행.
- 운영 업로드: `workflow_dispatch`이고, `refs/heads/main`이며, `deploy_to_production`을 명시적으로 체크한 경우에만 실행.
- Firebase 인증·환경변수·실제 서비스 설정은 변경하지 않는다.

GitHub의 [workflow 입력과 job 조건 문서](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax)를 기준으로 Boolean `inputs`와 job-level `if`를 사용했다. README, DEPLOYMENT 및 배포 진단 메시지도 같은 방식으로 정리했다.
