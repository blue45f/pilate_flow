# 2026-11-14 모션 이미지·참고 영상 개선

## 반영 범위

- 98종 동작의 인물 외형을 imagegen 공통 atlas로 맞췄다. 원본 PNG는 `docs/design/motion-atlas-v3/source/`에 보존하고, 실제 화면에서는 투명 WebP를 사용한다.
- 동일한 관절 좌표에서 시작·정점·마무리의 294개 프레임을 640×400 WebP로 생성한다. 총 2,768,078 bytes, 프레임당 평균 9,415 bytes다. 직전 커밋의 SVG 캐시 3,894,134 bytes에 비해 원본 파일 합계가 28.9% 줄었다. 이 수치는 네트워크 압축 후 전송량이나 측정된 화면 속도를 뜻하지 않는다.
- 정적 목록에서는 프레임 캐시를 사용하고, 상세·연속 모션에서는 같은 작성 모델을 지연 로딩한다. 프레임 또는 공통 인물 이미지가 실패하면 해당 동작의 벡터 모델로 돌아간다. 인물의 방향은 손·발의 순간 위치에 따라 뒤집히지 않는다.
- 기구 참고 이미지도 같은 색감으로 맞췄다. 인물이 닿는 지지면과 움직임 경로는 기존에 직접 작성한 기구 좌표를 따른다.
- 새 공유 이미지 2장은 PWA 셸 캐시에 포함한다. 해시가 들어간 WebP 동작 프레임은 사용 시 캐시한다.

기본 동작 라이브러리는 158종이다. 이 중 98종에 직접 작성한 모션 모델이 있고, 추가 영상 참고 동작 60종은 기구 그림과 참고 영상을 사용한다. 전용 모션이 없는 항목에 다른 동작의 신체 그림을 대응시키지 않는다. 이미지는 수업 설계를 돕는 자료이며 전문가의 동작·해부학 검수를 마친 자료로 표시하지 않는다.

## 여러 참고 영상

공용 영상 카탈로그는 350개(국내 76개·해외 274개)다. 이번 변경에는 신규 40개가 포함되며, 조사 근거는 `docs/research/additional-pilates-videos-2026-11-14.md` 및 대응 JSON에 있다. 별도 수집 목록까지 합친 탐색 풀의 고유 영상 ID 406개와 공용 카탈로그 350개는 서로 다른 집계다.

| 범위 | 동작 수 | 영상 2개 이상 | 영상 1개 | 연결 영상 없음 |
| --- | ---: | ---: | ---: | ---: |
| 기본 라이브러리 | 158 | 55 | 60 | 43 |
| 별도 수집 목록 | 60 | 17 | 42 | 1 |

매트 브리지, 체스트 리프트, 싱글 레그 스트레치 준비는 각각 3개, 리포머 클래식 풋워크는 7개의 참고 영상이 연결된다.

상세 화면에서 썸네일을 골라 영상을 비교하고 국내·해외로 필터링한다. 썸네일은 큰 이미지 → 작은 이미지 → 제목을 유지한 대체 표시로 복구한다. 선택한 영상만 사용자가 열었을 때 재생기를 불러오며, Escape로 닫으면 실행 버튼에 포커스가 돌아간다. 탭을 숨기거나 화면을 나가면 재생기를 내린다.

영상은 동작명 일치·관련 변형·복합 흐름의 구성 동작·저장한 참조로 구분한다. 제작자 페이지와 oEmbed 제목·채널 확인은 실제 시범 또는 특정 구간의 정확한 일치를 증명하지 않는다. 이번 검토에서 전체 영상의 실시간 공개 상태나 재생 성공을 검증했다고 주장하지 않는다.

## 화면 구성과 수업 작성

- 일상 탐색은 `동작 라이브러리`에서 검색·기구 선택·상세 보기·수업 추가로 이어진다.
- 종전 `모션으로 살펴보기`의 공통 패턴은 `자료와 고급 도구 → 패턴 도해 초안`으로 이름을 바꿔 접힌 상태로 둔다. 사용자가 확장했을 때만 도해를 렌더링하고, 닫기·검색 전환 시 포커스를 복구한다.
- 수업 작성의 추가 위치를 맨 앞·맨 뒤·선택한 항목 뒤에서 고를 수 있다. 연속 추가는 방금 추가한 항목 뒤로 이어지고, 추가 결과에서 해당 행으로 이동할 수 있다. 잠긴 항목의 순서와 삭제된 기준 항목에 대한 보호는 기존 저장소 규칙을 따른다.
- 아직 저장 ID가 없는 수업에서 최근 추가 정보가 없을 때 화면이 중단되던 null 접근을 수정했다. 기존 초안의 동작과 저장 데이터는 유지한다.

## 검증과 배포 기록

검증 환경은 Node.js 24.22.1, pnpm 11.25.0이다. 자세한 숫자와 검사 방식은 `motion-video-release-2026-11-14.verification.json`에 기록했다.

| 검사 | 결과 |
| --- | --- |
| 최종 `pnpm build` | TypeScript·Vite·PWA 검사 통과, 엔트리 `/assets/index-BKRMtVS7.js` |
| `pnpm lint` | 오류 0개, 기존 Fast Refresh 경고 1개; 최종 수정 파일 검사 오류·경고 0개 |
| `pnpm test`와 수정 파일 재실행 | 전체 실행 후 5개 파일을 수정·정리하여 33개 재검증 통과. 합산 3,432개 통과, Chromium 검사 2개 실행 제한 |
| 예약·반복 엔진 | 93개 통과 |
| 배포 스크립트 | 55개 통과 |
| 모션 스터디·이미지 생성기 | 각각 6개 통과, 98종·294개 프레임 무결성 통과 |
| 비밀키 검사 | 7개 검사기 테스트 및 새로 추가한 소스·테스트·문서·설정 스캔 통과 |

전체 Vitest 최초 실행은 372개 파일에서 3,425개 통과·6개 실패·2개 건너뜀으로 종료됐다. 실패한 일반 테스트 6개는 수업 상태 null 접근, 소도구 테스트 준비 데이터, 지연 로딩을 기다리지 않던 테스트, Git 인덱스에 남아 있던 삭제 예정 SVG 읽기 때문에 발생했다. 해당 5개 파일의 최종 재실행은 새 회귀 테스트 1개를 포함한 33개 모두 통과했다. 따라서 위 3,432개는 전체 실행과 수정 파일 재실행을 결합한 결과이며, 단일 전체 실행이 모두 통과했다고 기록하지 않는다.

`classCueSheetChromium.test.ts`의 실제 화면·인쇄 검사 2개는 Chromium이 `socket() failed: Operation not permitted`로 시작하지 못해 실행되지 않았다. 별도 모바일·데스크톱 브라우저 검사도 같은 실행 환경 제약으로 완료하지 못했다. 검사 자체를 건너뛰도록 코드를 변경하지 않았다.

Firebase 배포 대상은 기존 `deskcloud-fleet-auth` 프로젝트의 `pilates-flow-atelier`다. main push는 품질 검사·산출물 생성만 수행한다. 운영 업로드는 기존 수동 배포 workflow를 사용하고, 반영 여부는 해당 배포 로그와 운영 엔트리·에셋 대조 결과로 확인한다.
