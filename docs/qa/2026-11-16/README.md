# Pilates Flow · 검색부터 수업 시작까지의 검증 기록

기준: 원격 main `26d5c5f0ab2f120d3d924578695c7203f2c9bb27`. 변경 작업은 `feat/simple-flow-natural-motion-20261116`에서 통합했다. 이 기록은 브라우저에서 재현한 결과, 회귀 테스트, 시각 검토의 범위와 한계를 구분한다. 실제 병합 SHA와 원격 CI 결과는 최종 PR 기록에서 확인한다.

## 범위와 중복 감사

공개 경쟁 서비스의 검색·목록 추가·계획 복귀 흐름을 참고했다. 현재 세션에는 REA 도구가 없어 새 REA 실행 결과로 주장하지 않는다. 경쟁 서비스의 코드·이미지·영상은 가져오지 않았으며, 로그인 기능이나 접근 제한을 우회하지 않았다. 조사 출처와 판단은 [공개 흐름 조사](../../research/competitor-usability-2026-11-16.md)에 있다.

수정 전 원격 main과 열린 PR을 확인했다. 기존 PR #2–#5의 진행 보호·일정·복구 기능은 이미 병합되어 있었고 열린 PR은 0개였다. 따라서 일정 시작 gate나 중단 복구를 새로 구현하지 않았다. 해당 경로의 기존 **8개 파일·98개 테스트**를 다시 실행했다. 준비 경고/시간 충돌이 모두 시작 차단 조건인 것은 아니며, 브라우저 종료 후 실행 중 타이머의 영속 복구는 이번에 입증하지 않았다.

## 실제로 재현한 마찰과 바뀐 동선

우선 제거한 마찰은 **이미 담은 동작의 버튼을 다시 누르면 중복 오류로 끝나는 경로**다. 변경 전 PC와 390px 화면에서 매트 브리지를 한 번 담은 뒤 같은 카드 버튼을 눌렀다. 항목은 늘지 않았지만 “같은 동작의 중복 구성은 추가할 수 없습니다” 안내가 발생했다. 이 버튼은 시퀀스로 가는 다음 행동을 제공하지 않았다.

변경 후에는 추가 버튼이 **수업에 담기 → 수업안 보기**로 바뀐다. 다시 누르면 현재 수업안을 열며, 브리지 1개·4분·같은 수업 이름이 유지된다. 저장소 전체 비교 회귀는 `activeTab` 이외의 수업·조건·undo·일정·기록 데이터가 바뀌지 않음을 확인한다.

| 단계 | 변경 전 관찰 | 변경 후 확인 |
| --- | --- | --- |
| 검색·필터 | “필터”가 “자료와 고급 도구” 화면을 열어 기본 라이브러리를 벗어남 | 난이도·동작 시간·보유 장비 조건을 라이브러리에서 조절. 검색어·결과 유지 |
| 추가 | 카드의 추가 버튼은 담긴 뒤에도 중복 추가 요청을 실행 | 한 번만 추가하고 같은 위치에 “수업안 보기” 표시 |
| 미리보기 | 이미지·제목·하단 보기 버튼이 같은 상세 화면을 각각 열음 | 이미지와 제목을 하나의 미리보기 대상으로 통합. 즐겨찾기와 수업 버튼은 독립 |
| 수업안 복귀 | 카드 버튼에서 중복 오류가 발생한 뒤 별도 수업안 이동 필요 | 담긴 카드에서 한 번의 행동으로 현재 수업안 복귀 |
| 수업 시작 | 기존 준비 화면과 시작 동작 | 같은 시작 경로를 재사용. 동작 수와 계획을 보존한 채 실제 타이머 시작·일시정지 확인 |

추가로 재현한 두 회귀도 좁게 수정했다. 다른 초안으로 바뀌었을 때 이전 추가 성공 안내가 남는 문제는 현재 수업·실제 남은 동작에 맞춰 제한했다. 즐겨찾기만 보는 중 해제해서 카드가 사라질 때는 검색창으로 포커스가 돌아간다.

## 격리된 브라우저 증거

기준 앱은 `127.0.0.1:5175`, 변경 앱은 `127.0.0.1:5176`에서 실행했다. 두 origin의 로컬 데이터만 사용했고, 빈 수업에서 시작해 `QA 20261116 초보 강사 흐름`이라는 더미 이름과 매트 브리지 한 항목을 사용했다. 운영 사이트·회원·일정·진행 기록은 수정하지 않았다. 진행 테스트의 종료는 더미 수업에서 “기록 없이 나가기”로 처리했다.

변경 전 PC는 직접 열린 Chromium의 1348 × 936 콘텐츠 영역에서 확인했다. PC 변경 후 및 모바일 비교는 [반응형 테스트 화면](responsive-harness.html)에 실제 앱을 iframe으로 열어 **1280 × 844 / 390 × 844 CSS viewport**를 만들었다. 이 페이지는 대상 주소를 위 로컬 두 곳으로 고정하고, 앱의 저장소나 DOM 상태를 주입하지 않는다. 모든 검색·선택·시작은 앱의 정상 UI를 조작했다. 스크린샷과 접근성 트리는 `browser/`에 함께 보관한다.

개발자 도구 에뮬레이션은 환경 정책으로 사용할 수 없었으며 제한을 변경하지 않았다. iframe은 실제 CSS 미디어 쿼리와 반응형 동작을 검증하지만 휴대폰 OS·터치 센서·모바일 Safari를 에뮬레이션하지 않는다. 최종 증거에는 임시 브라우저 확대 실험이나 갱신 중의 화면을 포함하지 않는다.

브라우저에서 추가 확인한 내용:

- 이미지 영역 클릭으로 미리보기 열기, 키보드 Enter로 열기, Escape로 닫기 및 호출 버튼 포커스 복귀.
- 필터 Escape/결과 보기 뒤 트리거 포커스 복귀, 검색 조건을 적용해도 수업 기구·목표 시간이 바뀌지 않음.
- 즐겨찾기 전용 결과에서 해제하면 카드가 사라지고 검색창이 포커스를 받음.
- 미리보기만 열었을 때 앱 내부의 원본 영상 iframe은 0개. 원본 영상은 자동 재생하지 않음.
- 모션 한 주기가 끝난 위치 1000, 정점 500, 마지막 프레임 1000으로 이동. 시작 자세 겹침은 기본 해제.
- 수업 시작 뒤 실제 일시정지 제어 표시. 이탈 요청을 취소하면 같은 동작과 이어서 진행 제어 유지.
- 원본 이미지가 로드된 새 미리보기의 generated practitioner opacity가 1이며, 앱 소스에서 발생한 console error/warning은 점검 시 발견하지 못함. 브라우저 확장의 로그는 앱 오류와 구분함.

각 캡처의 viewport·스크롤 폭·파일 SHA-256은 [브라우저 증거 목록](browser/evidence.json)에 기록했다. 360 × 800과 768 × 900에서도 라이브러리의 문서 가로 넘침이 없음을 추가 확인했다. 360px에서 미리보기 버튼은 높이 44px, 수업안 보기 버튼은 약 47.6px였다. 이 검사는 실제 페이지 전체의 넘침과 해당 두 제어의 크기를 확인하며 모든 자식 요소의 품질 인증은 아니다.

PC 전후는 서로 다른 viewport의 기능 비교이며 픽셀 단위 비교가 아니다. 모바일 미리보기 캡처도 변경 전은 시작, 변경 후는 정점이므로 같은 자세의 시각 비교는 아래 모션 시트를 사용한다.

접근성 트리와 실행 로그는 캡처 원문을 보존한다. UI 텍스트의 끝 공백이나 도구 출력의 마지막 빈 줄도 정리하지 않아 해당 증거 파일에만 Git 공백 경고가 남을 수 있다. 제품 소스와 작성한 문서는 별도로 공백 검사를 통과했다.

## 모션·이미지

기존 practitioner atlas의 바이트를 유지하면서 렌더링 연결을 조정했다. 매트 브리지, 패럴렐 풋워크, 체어 시티드 호흡, 체어 스탠딩 페달을 시작·중간·끝 자세로 비교했다. 발바닥 기준점 유지, 몸통/골반/허벅지 연결, 목의 틈, 이중 윤곽과 반투명 중첩을 살폈다. 첫 수정안의 큰 원형 골반 패치는 시각 검토에서 제외하고 연결부 아래의 좁은 형태로 고쳤다.

[대표 4종 비교·회귀·한계](motion-renderer/README.md)와 [프레임 입력/출력 해시](motion-renderer/contact-sheet-inputs.json)에 자세한 근거가 있다. 원본 atlas·rig 좌표·motion sampler·자료 검토 상태는 바꾸지 않았다. 98종의 294개 캐시 프레임을 새 renderer와 일치하도록 갱신했다. 캐시 총용량은 2,768,078에서 2,689,722 bytes로 2.83% 줄었으며, 이는 파일 용량 비교이지 실행 성능 측정 결과는 아니다.

이 결과는 계획용 2D 도해의 렌더링 개선이다. 단순화된 체형과 일부 지지면 실루엣 겹침은 남는다. 전체 동작의 해부학 정확성, 전문가 검토 완료, 원본 영상 프레임 일치, 개인별 수행 적합성을 주장하지 않는다.

## 미검증·제외 항목

실제 iOS/Android 기기, 모바일 Safari, 터치/스크린리더, 기기 한국어 음성·Bluetooth·진동, 전체 동작의 연속 프레임 시각 검토, 경쟁사 대비 실제 사용자 완료 시간은 검증하지 않았다. 현재 브라우저에 한국어 기기 음성이 없어 음성 없는 진행을 확인했다. 브라우저 종료 후 실행 중 타이머의 영속 복구도 검증하지 않았다.

새 유료 이미지 작업, 운영 배포, 운영 데이터 변경은 수행하지 않았다. 자동 workflow의 운영 배포 job은 수동 배포 입력이 명시적으로 참인 경우에만 실행되는 기존 조건을 유지한다. 이번 결과는 검증한 변경을 원격 main에 병합하는 범위다.
